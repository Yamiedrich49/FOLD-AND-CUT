## 目的と譲れない方針

7歳前後から遊び始められ、500問を通じて折り紙の対称性、折り目、重なり、展開を考える力を徐々に身に付けるスマートフォン向けパズル。単に難問を量産するのではなく、序盤から「考えて分かった！」という体験を積み重ねる。

- 指のドラッグを中心とした直感的な操作と、見て分かるアニメーションを優先する。
- ミニマルで美しい画面、気持ちのよい正解演出・音色。不協和音は避ける。
- 選択肢の差が「ほんの少し位置がずれるだけ」の見分け問題にならないこと。
- 反復に見える問題、序盤の退屈さ、突然の難易度上昇を避ける。
- 既存の500問、各種操作、ヒント、記録を不用意に削除・破壊しない。
- 仕様変更後は実機でのプレイを重視する。単にコードが動くことと楽しいことは別。

## 現行の操作

1. FOLD: 折り線と青い矢印を見ながら紙をドラッグして折る。必要に応じて複数回。
2. CUT: オレンジ色の切り込みをなぞる。複数箇所ある場合は順番に進む。
3. THINK: 展開後の模様を選択肢から選ぶ。長押しすると選択肢が拡大できる。ヒントもある。
4. UNFOLD: 折った順番を逆にたどり、展開アニメーションを確認。結果・正解形を表示。
5. 章・問題番号表示をタップすると20章×25問から選べる。効果音切替、戻る操作あり。

## ファイル構造（v7）

- `index.html`: UI/CSS/ゲームロジック。外部ビルド不要の静的Webアプリ。
- `data/fold-000.js`〜`data/fold-015.js`: 折り方テンプレートを分割した文字列。計480テンプレート。
- `data/puzzle-000.js`〜`data/puzzle-039.js`: 問題データを分割した文字列。計500問。
- `README.md`: 概要と当文書への案内。

**重要**: `window.__FC_FOLDS` / `window.__FC_PUZZLES` に分割文字列を積み上げ、`index.html` 側で `join('')` → `JSON.parse` する仕組み。分割ファイル単体は完全なJSONとは限らない。ファイル名・読み込み順を変えたり、一部だけ消したりしない。

問題オブジェクトには章番号、問題名、難易度、`foldTemplate`、切り込み、選択肢、正解位置、展開アニメ、誤答差分、ヒント等を含む。折り操作はテンプレートを介して展開する。

## 2026-11-06 触り心地の改善（MASTER 500 v7 UI polish）

旧UIに対する試遊フィードバックを受け、`index.html` のみ変更。全500問と分割問題・折り方データはそのまま維持。

- **UNFOLD**: 展開速度を1ステップ650ms→320msに短縮。冒頭とステップ間の待ち時間も短縮し、紙が「パサッ」と開いてすぐ収まる動きに変更。効果音も短めの紙音に調整。スローでヌルヌルした動きを避ける。
- **CUT**: 線をなぞる操作を廃止。オレンジの切り込み・線を**指で1回タップ**する方式に変更。SVGの切断領域または実際の切断エッジへの近接判定を使用し、少し指が動いた程度では誤作動しない。タップの直後に切り抜きが消える。カット線の点線も廃止。
- **FOLD**: 点線の長い矢印、二重丸のつまみを廃止。薄い折り目の実線＋短い細線矢印＋単独の小さい青点に変更。薄い過去の折り目、控えめな外枠。各折りステップでガイドを再表示。

**保留の検証**: GitHub Pages/iPhone実機上での初回描画、通常の一折り・複数折り、複数切り込みのタップ、予想・展開・記録を確かめること。現時点では公開ページのブラウザ実動作を確認できていないため、完了とはみなさない。

## 次回以降の改善・検証ポイント

1. **公開動作確認**: iPhone Safari/ChatGPT内ブラウザで起動、データロード、ドラッグ、カット、選択、展開、次問、再読み込み後の保存を確認。GitHub Pages設定・デプロイも確認。
2. **難易度の滑らかさ**: 特に1〜25問の退屈さ・重複感、章境界での難易度ジャンプを検証。問数を増やすより質の高いステップを重視。
3. **選択肢の品質**: 正答と誤答の違いが図形として十分に見えることを確認。微細な単純位置ずらしではなく、折り方の理解から生じる誤りを扱う。
4. **スマホ性能**: 多数の同期スクリプトと大きな幾何学データによる初回ロード・メモリ利用を実機で測定。既存の分割機構を崩さず改善する。
5. **操作フィードバック**: 現状のCUTは線との一致精度ではなくスワイプ距離で完了判定している。遊びとして適切か確認。演出と音の音量・音程も検証。
6. **回帰テスト**: 1, 25, 26, 100, 250, 400, 500問で基本動作／進捗保存／画面のはみ出しを試す。可能なら全問の正解参照・選択肢重複・テンプレート参照を自動検証する。

## 開発ワークフロー
